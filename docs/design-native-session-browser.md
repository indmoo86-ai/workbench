# Native session browser

Status: implemented. This is a native CLI entry, not another web chat implementation. Deployment of a particular revision is verified separately from the code and acceptance boundaries below.

## Interface

- The left heading switches between Group chats and Sessions using two joined buttons without a surrounding frame. Only the outer ends are rounded; the middle seam is straight. Existing columns, header and mobile drawers are reused.
- Sessions defaults to All sessions and All Agents. The unfiltered view combines independent histories, dialog-created entries and managed group sessions across devices, using the existing bounded catalogue reads without starting a CLI. Entries retain their titles and last-update times, using the group-list card style.
- The compact source/device filter offers All sessions, Created sessions, Group chats, Local machine, Servers and Other devices. The Agent filter offers all Agents or Codex, Claude Code, Grok and Agy. Group history is separated by exact managed native IDs; explicit device views include independent vendor histories and dialog entries, not those group histories. Node categories reuse the existing Worker node-kind metadata. User-selected filters survive refreshes; failed refreshes retain only the failed scope's existing entries.
- The list has a right-aligned transparent scrollbar track. A double-chat-bubble plus icon is the new-entry button in both modes. There is no manual session-refresh button: operations, returning to the page and a foreground-only 30-second check refresh automatically. Concurrent refresh intents are coalesced, and selection/scroll positions are retained.
- Selecting a conversation shows read-only user/assistant history in the middle, rendered with the group-chat row/bubble structure, and grouped device/tool and native ID/folder cards in the right pane; the ID and folder have copy buttons.
- Takeover: a bottom bar keeps the view read-only until the user clicks Take over session. The footer then becomes the group-chat composer layout (Enter sends, Shift+Enter breaks lines, an unconfirmed send keeps its client ID and retries without dispatching twice, a running reply can be stopped). End takeover returns to read-only. Takeover state and drafts are per-browser-tab session storage. Attachments (upload button, paste, drag; at most 6, 20 MB each) are stored in a separate `native-turn-attachments` folder and `nativeTurnAttachments` records owned by `native:<device>`; @mentions and quoting are not offered.
- The shared new-session dialog requires a title and chooses a device, tool and allowed working folder. The title is Workbench metadata, never a prompt or a replacement for native instructions. Permission bypass is an explicit checkbox, initially off; otherwise the CLI's own defaults apply.
- New and continue dialogs share a compact responsive layout and icon-only close control. Their separate file/folder picker lists metadata from the selected device within its allowed roots, with parent navigation and pagination. Selecting a file uses only its containing folder as the working directory; no file content is read, uploaded or sent to the CLI. Selecting a folder uses that folder. Existing sessions retain their original working directory, including when selecting a file through the picker.
- The role terminal dialog also opens this same new-session form, preselecting only its device and tool. It does not supply the group folder, history or role prompt. The separate history action verifies the latest resumable Run; older records remain stored, and active terminal claims keep their original binding and return controls.
- Continue prepares an exact native resume, not latest/continue/fork. Known original working folders cannot be silently changed. Unknown folders must be selected explicitly.
- The final link opens iTerm. A registered remote device uses the existing SSH command builder and the Worker's original user/environment. Copying the command is also available.

## Boundaries

`GET /api/native-sessions/:nodeId` selects `runtime`, `scope=created|group|all` (default `created`) and optionally an exact `sessionId`. The `all` scope is the explicit independent-device view; known managed IDs are excluded. Folder browsing uses the same node's allowed-root query. `POST /api/native-sessions/:nodeId/terminal` prepares or releases a single-use terminal entry, accepting a title for a new entry and an optional `entryId` when reopening the same unstarted entry. These routes require the normal human API credential, not an Agent tool credential. Workers advertise `nativeSessions:2`; old Workers display an upgrade error rather than returning an unfiltered list.

`nativeCatalogEntries` keeps the stable entry ID, title, device, runtime, folder, timestamps, launch state and exact native ID when known. It is separate from terminal operation IDs and raw transcripts. Home retains a metadata copy for offline display. Closing an unopened prepared link leaves a draft that can be reopened with the same entry ID; no historical records are deleted. Claude and Grok use their supported explicit fresh-session UUID argument. For a CLI without that argument, the launcher can associate a vendor history file only from writable file descriptors of its verified native process; ambiguity or missing process evidence leaves the entry unlinked. It never guesses from the newest file, folder or timestamp. An unlinked launched entry has no fabricated resume action. This process observation does not send input, stop a process or change native history.

History IDs resolve only inside the selected tool's vendor directories. Reads skip symlinks, subagent folders and non-history files. Discovery is bounded to 20,000 entries and returns up to 100 recent distinct IDs; oversized transcripts are read in windows and explicitly marked partial. Credential/configuration files are not exposed. Codex, Claude and Grok messages are parsed only as user/assistant text, not executed or interpreted as platform commands. Agy DB/protobuf content currently has no decoder, so it shows metadata and the native terminal entry instead of a fabricated empty conversation.

Native terminals reuse the existing prepared/active/released lease, process-identity checks and five-minute unopened-entry expiry. Ownership is resolved by device, CLI and exact native ID from saved role sessions and historical Runs before considering current folder bindings. Moving a project folder does not make its old sessions independent. Ambiguous ownership, an unknown historical device or a different folder owner blocks preparation. Home, Worker and the launcher recheck the binding; `nativeTakeover:1` is required to prepare with this contract. Existing managed execution is never stopped by preparation.

The same project lock protects dispatch, terminal preparation, role-history clearing/reset, CLI switching, project deletion and managed cross-device reads. Legacy terminal-only claims that own a known group native ID also block that group without rewriting the old claim or history. An unrelated folder still uses a terminal-only scope. A finished CLI remains reserved until the Worker verifies its exit; offline or unknown process identity never silently releases a lock.

Session details show terminal occupancy, the affected group when known, the last check and any process error. Return to platform checks for exit without stopping a process; Stop CLI and return requires confirmation and targets only the saved claim. These actions use the same endpoints as the role terminal dialog. A related group's other takeover blocks a new entry; unknown ownership is shown explicitly. The controls update from existing state snapshots, with no additional polling. Background return after CLI exit and five-minute unopened-link expiry remain unchanged. Closing an unused dialog requests release; copied/opened links retain the lease until expiry or native exit.

Previewing injects no role responsibilities, Workbench platform prompts, managed `wb` context or model requests. Native CLI history, login and model selection remain owned by the native CLI. Previewing does not create a Task/Run, send a prompt, synchronize files or modify existing histories. Page takeover requires a separate execution-permission confirmation described below; interactive approval remains available through iTerm.

## Takeover turns

- Resident process: one per taken-over session. Codex keeps an app-server (`thread/resume` once, then `turn/start`; Stop sends `turn/interrupt`). Claude keeps `-p --input-format stream-json --output-format stream-json --resume <id>`; Stop sends an interrupt control request and closes the process only if it does not settle within 10 seconds. Agy uses its `--conversation <id> --input-format stream-json` mode. Grok has no resident input mode and is started per turn with `--resume`. The process closes on End takeover, after 30 minutes idle, or on device disconnect; the CLI slot count counts each resident process once.
- Images: Codex receives `localImage` input items and Claude base64 image content blocks. Grok and Agy refuse images with a clear error; other files are passed as local paths.
- Process view: each turn stores ordered events (text, intermediate messages, tools with arguments/result/status, errors) and a phase (starting, thinking, tool, replying, waiting). The page renders them with the group-chat live-scene projection, read-only imported, and anchors the stored block after the matching reply after history is re-read.
- Resource bounds: tool packets are bounded before WebSocket transmission; a turn retains at most 128 KiB of process events. Indexed queries select the current session before parsing stored bodies, and oversized history responses omit older process detail. Streamed text and tools do not broadcast full-workspace refreshes to other pages. Unreferenced draft attachments can be removed; files referenced by recorded turns remain protected.

`POST /api/native-sessions/:nodeId/turns` takes `runtime`, exact `sessionId`, a client `clientTurnId`, `text` (at most 12,000 characters), optional attachment IDs and `allowAll:true` after the page confirms automatic tool execution. It is idempotent by `clientTurnId` and refuses a second concurrent turn for the same native session. Both Home and Worker reserve a `native-turn` lease in the existing `terminalSessions` records, sharing native identity, project/folder exclusion and device capacity with managed Runs and iTerm. `GET .../turns?runtime=&sessionId=` lists recent turns; `POST .../turns/:id/stop` stops one. Home stores bounded `nativeTurns` and creates no Task, Run, project or role. Workers advertise `nativeTurns:3`; earlier page-takeover implementations are refused because they do not provide the shared lease and exit-confirmation contract.

The Worker re-reads the exact history ID and resolves its original folder inside allowed roots (unknown folders are refused), then checks ownership again before input. Codex resumes through the App Server without model, developer-instruction or environment overrides; other adapters use their exact native resume flags without Workbench rules or model flags. A different returned native ID stops the turn. Confirmed print/stream turns auto-approve tools (Codex retains its workspace-write sandbox). Saved process identity keeps the shared lease until exit is verified; a disconnect, restart or an unconfirmed stop remains occupied pending reconciliation. Ending takeover acknowledges the request first and the page waits for verified closure before showing it as ended. Worker shutdown closes its owned resident processes. After a successful turn the page re-reads native history and anchors the process record to the corresponding reply.

## Verification and limits

- Integration verification uses an isolated real Home and Worker with controlled native CLI executables: shared-group exclusion, repeated turns and images on one PID, oversized tool messages without disconnect, interruption followed by another turn, verified release, Worker SIGTERM and restart recovery. A real browser additionally checks permission cancellation, old consent-state rejection, cross-session drafts and a delayed real POST response. These checks do not substitute for authenticated model execution against every vendor.

- Takeover: `tests/native-turns.test.mjs` covers idempotent sending, refusal of invalid input, old Workers and occupied sessions, event ordering, disconnect/restart handling, mismatched native IDs, unknown folders, argument injection boundaries controlled Claude/Grok executables, resident reuse, interrupt, idle close, image delivery for Codex and Claude, file hash verification and isolation from the shared adapters. An isolated Home and Worker with a controlled CLI were exercised through the HTTP API and a headless browser (take over, send, stream, finish). Paid vendor-model turns were not run.

- Isolated catalogue tests cover exact IDs, tool separation, preserved history text, permission flags, symlinks and occupied-session/folder rejection.
- A real isolated Home and full Worker exercise HTTP/WS reads, exact-resume terminal preparation, idempotent links, duplicate rejection, allowed-root validation, release and automatic return. That test uses a controlled CLI executable and does not claim vendor-model execution.
- Real native histories on a Mac and Linux server were read without modifying their state: all four tools were listed; three yielded text previews; Agy remained metadata-only.
- A real browser exercises switching, central preview, details and the default-unchecked permission option using a controlled native-history response. The existing suite and syntax checks are also run.
- The catalogue revision adds isolated Home/Worker tests for default/group/device scope separation, title persistence, idempotent preparation, reopening a draft without duplicating its entry, exact process-file association and offline metadata. Browser checks cover compact filters, title entry, operation/focus refresh (including a delayed pre-creation response), desktop/mobile layout and preserved group navigation.
- A browser connected to a real isolated Home and Worker, without mocked API responses, creates a titled entry, reloads it, reopens its draft, invokes the returned launcher with a controlled CLI, previews its exact recorded output and retains the title offline. Cancellation of a prepared resume preserves the existing ID; a subsequent launch uses exact resume arguments. Dead-process reconciliation does not leave the catalogue permanently active.
- End-to-end iTerm GUI interaction and paid/native model turns across all four vendors remain release-acceptance work. A browser protocol link alone does not prove an SSH login or a successful model reply.
